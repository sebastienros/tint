# Fuzz campaign, 2026-10-25

`tools/Tint.Fuzz` (see its [README](../../tools/Tint.Fuzz/README.md)) against TextMateSharp 2.0.4 (Onigwrap) reading
the same grammar files, every bundled grammar, Dark+ on both sides; token and style findings judged by vscode-textmate
9.3.2 over vscode-oniguruma (`tools/Tint.CorpusCheck/referee`, every grammar loaded).

- Machine: Apple M4 Pro (macOS 15.8.1 arm64, 14 cores), .NET 10.0.11.
- Seed 20261025, 20 minutes (20 min 21 s with the last inputs), 12 workers; per-line time limit 10 s on both sides;
  lines over 1 s reported; a line over 60 s is a hang.
- 12,484 inputs, 731,709 lines, 37.6 million characters over the 84 grammars (140 to 560 inputs per grammar: an input
  with a long line holds its worker longer).
- Time spent tokenizing, summed over threads: Tint 585 s, TextMateSharp 12,623 s.

### Referee version

The referee runs the vscode-textmate 9.3.2 release from npm (January 2026); Tint ports `main` at `392b23a4`, which
adds three source changes since: an empty or missing `end` matches immediately (#252), back-reference escaping
mirrors TextMate 2.0 (#276), and the `TokenHandler` refactoring (#261). One finding is #252: VS Code's XML comment
rule has an inner `begin` (`--(?!>)`) without `end`; on `<!------`, Tint (like `main`) pops it at once and marks the
second `--` invalid again, the release keeps it open with `\uFFFF` as its end. The vscode-textmate suites in the
repository pin `main`'s behavior (`suite1` case "Issue #251 empty `end` match immediately"). Building the referee
from `main` is left for later.

### Differences that stay

- Registry contents (CoffeeScript): vscode-textmate collects a grammar's dependencies from its patterns and includes
  but not from its captures, so `source.js`, which CoffeeScript embeds in a capture only, is not loaded when
  CoffeeScript is the only grammar asked for, and the backtick block is not retokenized. With `source.js` loaded (as
  in a Tint registry with the bundled grammars, or a VS Code session that opened a JavaScript file), vscode-textmate
  tokenizes exactly as Tint. The referee loads every grammar.
- The two engine findings below.

## Engine findings (for GregsEx)

Both come from GregsEx 0.5.1 as Tint configures it: patterns parsed with `RegexProfiles.OnigurumaTextMate` and
`OnigurumaCompileOptions.TextMate`, searched through one `OnigurumaScanner` per rule with the default match limits
(10,000,000 work units per search, 64 MiB workspace; `src/Tint/Internal/Regex/RegexCompiler.cs`). The inputs are in
[fuzz-2026-10-25-inputs.json](fuzz-2026-10-25-inputs.json), by `id`: tokenize `lines` in order from the initial
state with the grammar `scopeName` (a registry holding every bundled grammar); `line` is the 1-based line concerned.
vscode-textmate means 9.3.2 over vscode-oniguruma 2.0.1 (Oniguruma 6.9.x, whose retry limit applies per match
attempt at one start position, not per search).

### Work limit: `c-work-limit` (C)

- Grammar `source.c`, `grammars/cpp/syntaxes/c.tmLanguage.json` (VS Code `3ac0f056`). Line 3 of the input: a space,
  7,548 `:` characters, then `Py_DECREF(data);` (7,564 characters), inside a block opened on line 2.
- Pattern: `repository.c_function_call.begin` (304 characters), reached through `block` → `block_innards` →
  `#c_function_call`:

  ```text
  (?x)
  (?!(?:while|for|do|if|else|switch|catch|enumerate|return|typeid|alignof|alignas|sizeof|[cr]?iterate|and|and_eq|bitand|bitor|compl|not|not_eq|or|or_eq|typeid|xor|xor_eq|alignof|alignas)\s*\()
  (?=
  (?:[A-Za-z_][A-Za-z0-9_]*+|::)++\s*\(  # actual name
  |
  (?:(?<=operator)(?:[-*&<>=+!]+|\(\)|\[\]))\s*\(
  )
  ```

- A search from position 0 exceeds the 10,000,000-unit work limit (`OnigurumaScanner.LimitExceededCount` + 1, about
  170 ms) and counts as no match: the lookahead consumes the run of `::` possessively from every start position and
  fails at the end, so the work is quadratic in the run (about 28 million steps for 7,548 characters). A search from
  position 1 stays under the limit. Four more begin patterns of the grammar with the same `(?:…|::)++\s*\(` lookahead
  also exceed it from position 0: `function-call-innards.patterns[5]`, `function-innards.patterns[4]`,
  `preprocessor-rule-define-line-contents.patterns[4]` and `preprocessor-rule-define-line-functions.patterns[6]`.
- Effect: Tint scopes `Py_DECREF(data)` as a function definition (`meta.function.c meta.function.definition.parameters.c`);
  vscode-textmate finds the call (`meta.function-call.c`).
- `Tokenizer.LimitExceededCount` reports it on Tint's side. No corpus file reaches the limit.

### Slow lines

Warm (each input tokenized twice, the second run timed), one thread, the slowest line of each input, against
vscode-textmate and TextMateSharp on the same input. The campaign's own `tint-slow` timings ran on 12 busy workers
and include first use, so they are higher.

| Input id | Grammar | Line | Length | Tint | vscode-textmate | Ratio | TextMateSharp |
|---|---|--:|--:|--:|--:|--:|--:|
| `slow-yaml` | `source.yaml` | 1 | 11,134 | 217 ms | 1 ms | ~200x | 1 ms |
| `slow-latex` | `text.tex.markdown_latex_combined` | 1 | 3,530 | 237 ms | 44 ms | 5.4x | 1,690 ms |
| `slow-batch` | `source.batchfile` | 3 | 18,843 | 47 ms | 9 ms | 5.2x | 898 ms |
| `slow-tsx` | `source.tsx` | 19 | 13,858 | 5,204 ms | 1,493 ms | 3.5x | 318,534 ms |
| `slow-jsonl` | `source.json.lines` | 13 | 13,700 | 200 ms | 63 ms | 3.2x | 2,175 ms |
| `slow-csharp` | `source.cs` | 1 | 5,748 | 1,517 ms | 539 ms | 2.8x | 4,345 ms |

On the other `tint-slow` inputs Tint is as fast as vscode-textmate or faster (warm): TypeScript 18,785 characters
1,403 ms vs 1,560 ms, Dart 413 ms vs 425 ms, snippets 21 ms vs 100 ms, search results 258 ms vs 183 ms; PHP and SQL
were slow only on first use. Long lines are quadratic in every TextMate tokenizer (each token restarts the searches
from its end), and VS Code stops tokenizing lines over 20,000 characters by default
(`editor.maxTokenizationLineLength`). The patterns that cost GregsEx more than Oniguruma on these inputs are not
identified yet: per-pattern timing, as done above for the C line (parse each `match`/`begin`/`end`/`while` of the
grammar and time `OnigurumaScanner.FindNextMatch` on the slow line from the token starts), is the next step.
